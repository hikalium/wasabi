# Plan: IME の単文節漢字変換

目標: WasabiOS の日本語入力（`src/ime.rs`）に単文節漢字変換を加え、
「今日の天気は雨です」を変換できるようにする。各段階は1コミット・1概念で、
`book2/ch2:` 接頭辞を付けて ajimi でこの順に埋め込める粒度にする。

## 現状

- `src/ime.rs` はローマ字→かな変換までできている。スペースキーは
  「`pending_string` 全体が `きょう` に一致したら `今日`、それ以外は全角スペース」
  というハードコード。
- 確定済み文字列と未確定文字列の区別がない。`Console`（`src/cui.rs`）の
  `input_buf` は IME の `pending_string` の写しで、`render_ime_line` は
  両者の差分を Backspace と再描画で画面に反映している。
- `print!` の出力はシリアル、VRAM の `BitmapTextWriter`（`src/graphics.rs`）、
  TCP ミラー、LPSS UART の4系統へ同じ文字列として流れる。VRAM 側は文字ごとに
  8×16 または 16×16 のグリフを `draw_font_fg` で描く。
- 漢字のグリフは `third_party/unifont/chars_to_include.txt` に列挙して
  `make -C third_party/unifont` で `glyphs.txt` を再生成する。現在 `今日` のみ。

## 目標の入力手順

文節ごとにスペースで変換し、Enter で確定する。未確定の文節には下線が付き、
Enter で下線が消えて確定済みになる。

```
kyouno [Space] [Enter]   → 今日の
tenkiha [Space] [Enter]  → 天気は
amedesu [Space] [Enter]  → 雨です
```

文節は「自立語＋付属語」なので、辞書で引けるのは先頭の自立語だけ、残りの
助詞・助動詞はひらがなのまま残す。これが単文節変換の核になる。

## 実装段階

### 1. 未確定文字列の下線表示と Enter による確定

- `graphics.rs` の `BitmapTextWriter` に下線フラグを持たせ、ANSI の SGR
  シーケンス `\x1b[4m`（下線開始）と `\x1b[24m`（下線終了）を解釈して
  フラグを切り替える。フラグが立っている間はグリフ描画後にその文字幅ぶん
  最下行へ1ピクセルの線を引く。Backspace の消去はすでに 8×16 の矩形塗り
  なので下線も一緒に消える。シリアルと TCP 側の端末はこのシーケンスを
  そのまま下線として表示するので、4系統すべてで見た目がそろう。
- `cui.rs` の `Console` で `input_buf` を確定済み文字列専用にし、未確定文字列
  を別に持つ。IME の `UpdatePendingString` は未確定部分だけを表し、描画は
  「確定済みの後ろに下線付きで未確定」を出す。Enter は未確定があれば下線なし
  で再描画して `input_buf` に追記するだけで、未確定が空のときだけコマンドを
  実行する。Ctrl+Space での `set_pending(input_buf)` 同期は不要になる。
- `ime.rs` の変換ロジックは変えず、既存の `today_conversion` テストが
  そのまま通ることを確認する。
- 説明する概念: 確定と未確定の区別を、内部状態と画面表示の両方で持つ。
  未確定文字列がそのまま変換対象の文節になるので、読みの切り出しは
  この段階で達成される。

### 2. 辞書の導入（データ化）

- `きょう`→`今日` の if 文を `BTreeMap<&str, &[&str]>` の辞書に置き換え、
  `init_dict()` で `きょう`/`てんき`/`あめ` を登録する。スペースは
  「未確定文字列全体を辞書で引く」動作。
- `chars_to_include.txt` に `天気雨` を追加して `glyphs.txt` を再生成する。
- テスト: `tenki␣`→`天気`。
- 説明する概念: 変換規則をコードからデータへ分離する。

### 3. 付属語を残す最長一致（単文節変換の完成）

- 未確定文字列の先頭から辞書に載っている最長の語を探し、残りはひらがなの
  まま後ろに付ける。未確定が空なら従来どおり全角スペースを入れ、一致が
  なければ何もしない。
- テスト: `kyouno␣`→`今日の`、`tenkiha␣`→`天気は`、`amedesu␣`→`雨です`。
  目標の文をここで達成する。
- 説明する概念: 文節＝自立語＋付属語、最長一致。

### 4. 複数候補の巡回と自動確定

- `あめ`→`雨`/`飴` を登録して `飴` のグリフを追加する。
- 変換中の状態として「読み・付属語・候補番号」を保持し、スペース連打で
  候補を切り替え、Backspace は変換を取り消して読みに戻す。
- 変換中に別の文字を打ったら自動で確定して次の文節を始める。Enter を
  毎回押さずに続けて入力できるようになる。
- テスト: `ame␣␣`→`飴`、`ame␣␣␣`→`雨`。
- 目標の文には不要だが、変換 UI の本質なので独立した段階にする。

## 補足

- グリフ追加は使う段階のコミットに同梱すると、そのコミット単体でビルドと
  表示が通る。
- 第1段階の下線位置はグリフの最下行を使うため、`g` や `y` のように最下行
  までピクセルがある字形では下線と重なる。行の高さを 17 ピクセルにする案も
  あるが変更範囲が広がるので、最初は重なりを許容する。
- 第1段階での未確定中の IME オフ（Ctrl+Space）は、未確定文字列をそのまま
  確定させる扱いにして状態を単純にする。
- 入力手順の前提として、`kyou␣` の直後に `no` だけ打って `tenki` を続けると
  読みが `のてんき` になり、第3段階の先頭一致では引けない。文節の終わりで
  スペースを押す手順を本文で明示する必要がある。
